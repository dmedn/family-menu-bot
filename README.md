# family-menu-bot

Telegram-бот для семейного планирования завтраков и ужинов на неделю.
Им пользуются два человека: рецепты, избранное и меню общие, изменения одного сразу видны другому.

## Возможности

- **🍳 Рецепты** — просмотр списка, добавление (название + тип «Завтрак» или «Ужин»), удаление с подтверждением.
  Рецепт, который назначен в меню, удалить нельзя: бот покажет, в какие дни он стоит.
- **📅 Меню на неделю** — вид Пн–Вс с датами, завтраком и ужином; переключение «Пред. / Текущая / След.» неделя.
  Выбрать день → завтрак или ужин → блюдо; можно заменить блюдо или убрать его из дня (сам рецепт остаётся).
  В списке выбора только рецепты подходящего типа, избранные идут первыми.
- **⭐ Избранное** — список избранных, добавление и удаление из избранного.
- **❓ Помощь**, команды `/start` и `/help`.
- Доступ только у двух Telegram ID из настроек; остальным бот отвечает, что доступ ограничен.

## Стек

Python 3.13 · aiogram 3 · SQLite через SQLAlchemy 2.x (async) + aiosqlite · Pydantic Settings · uv · Ruff.

## Быстрый старт

Нужен [uv](https://docs.astral.sh/uv/).

```bash
git clone <адрес-репозитория>
cd family-menu-bot

uv sync                 # установить зависимости
cp .env.example .env    # затем заполнить .env (см. ниже)

uv run family-menu-bot  # запустить бота
```

Запускать нужно из корня проекта: `.env` и база данных ищутся относительно текущего каталога.
Остановка — `Ctrl+C`.

## Настройки

Читаются из переменных окружения и файла `.env`. Переменные окружения имеют приоритет.

| Переменная          | Обязательна | Описание                                                          |
|---------------------|-------------|-------------------------------------------------------------------|
| `BOT_TOKEN`         | да          | Токен бота                                                        |
| `ALLOWED_USER_ID_1` | да          | Telegram ID первого пользователя                                  |
| `ALLOWED_USER_ID_2` | да          | Telegram ID второго пользователя (должен отличаться от первого)   |
| `DATABASE_URL`      | нет         | По умолчанию `sqlite+aiosqlite:///data/menu.db`                   |
| `TIMEZONE`          | нет         | По умолчанию `Europe/Moscow`; определяет, какая неделя «текущая»  |

Пустое значение (`BOT_TOKEN=`) считается незаданным. При неверной конфигурации бот не запускается
и выводит, какие переменные нужно исправить (значения в сообщение не попадают).

### Как получить токен и Telegram ID

- **Токен:** напишите [@BotFather](https://t.me/BotFather), выполните `/newbot`, задайте имя и username (оканчивается на `bot`).
- **ID:** каждый из двоих пишет [@userinfobot](https://t.me/userinfobot) и копирует число из поля `Id`.

> `.env` и файлы базы данных исключены из git (`.gitignore`). Не публикуйте токен.

## База данных

SQLite, по умолчанию файл `data/menu.db` (каталог создаётся автоматически). Таблицы создаются при запуске, если их ещё нет;
существующие данные не затрагиваются. Миграций нет (Alembic не используется).

- **`recipes`**: `id`, `title`, `meal_type` (`breakfast` / `dinner`), `is_favorite`.
- **`menu_entries`**: `id`, `menu_date`, `meal_type`, `recipe_id`, `selected_by` (Telegram ID выбравшего).

Ограничения на уровне БД:

- `meal_type` — только `breakfast` или `dinner` (`CHECK`);
- на одну дату — не более одного завтрака и одного ужина (`UNIQUE (menu_date, meal_type)`);
- `recipe_id` — внешний ключ с `ON DELETE RESTRICT`: рецепт из меню удалить нельзя.

Соответствие типа блюда типу приёма пищи (завтрак ↔ `breakfast`, ужин ↔ `dinner`) проверяется в `services.py`,
потому что `CHECK` не умеет смотреть в другую таблицу.

Резервная копия — это просто копия файла `data/menu.db` (лучше при остановленном боте).

## Структура проекта

```
src/family_menu_bot/
├── __main__.py        # точка входа: настройки, БД, Bot, Dispatcher, polling, закрытие ресурсов
├── config.py          # Settings (Pydantic Settings)
├── access.py          # AccessMiddleware: доступ только для двух ID
├── services.py        # правила работы с рецептами, избранным и меню (async, над AsyncSession)
├── dates.py           # недели с понедельника, русские дни недели
├── formatting.py      # тексты недели/дня/списков, разбиение по лимиту Telegram
├── keyboards.py       # reply- и inline-клавиатуры, тексты кнопок
├── callbacks.py       # типизированные callback data
├── database/
│   ├── models.py      # Recipe, MenuEntry, MealType
│   └── session.py     # движок, фабрика сессий, init_db, close_db
└── handlers/
    ├── common.py      # /start, /help, главное меню
    ├── menu.py        # недельное меню
    ├── favorites.py   # избранное
    ├── pickers.py     # постраничный выбор рецепта (удаление, избранное)
    ├── recipes.py     # рецепты: список, добавление (FSM), удаление
    ├── fallback.py    # устаревшие кнопки и общий обработчик ошибок
    └── ui.py          # общие помощники для хендлеров
```

## Как это устроено

- **Доступ.** `AccessMiddleware` стоит на уровне `dp.update`, то есть до любых хендлеров. Посторонние получают короткий отказ,
  и ни одна команда или кнопка для них не выполняется.
- **Сессии БД.** Один движок на приложение; `session_factory` передаётся в хендлеры через workflow data диспетчера.
- **FSM** (в памяти) используется только для добавления рецепта. Удаление, избранное и меню работают через inline-кнопки
  с callback data и не зависят от состояния, поэтому переживают перезапуск бота.
- **Данные из кнопок не считаются доверенными.** Перед каждым изменением рецепт, его тип и состояние ячейки меню
  перепроверяются в БД, так как второй пользователь мог изменить данные раньше.
- **Одновременные действия.** Назначение блюда — один `INSERT … ON CONFLICT DO UPDATE`: дублей быть не может,
  при одновременном выборе в одну ячейку побеждает последнее действие.
- **Порядок роутеров** в `build_dispatcher` важен: роутеры с кнопками навигации идут раньше `recipes`
  (там есть хендлеры состояний FSM), `fallback` — последний.

## Разработка

```bash
uv run ruff format .       # форматирование
uv run ruff check .        # линтер
uv run python -m compileall -q src   # проверка синтаксиса
```

Тестовый фреймворк в проекте не используется. Если `uv run` жалуется на пересборку пакета
(например, в окружении с read-only `.venv`), добавьте флаг `--no-sync`.

## Ограничения

- Состояние незавершённого добавления рецепта хранится в памяти и теряется при перезапуске.
- Названия рецептов могут повторяться; максимальная длина названия — 100 символов.
- В рецепте только название, тип и флаг избранного: без ингредиентов, инструкций и фото.
- Список покупок, интеграции с ИИ и веб-интерфейс не реализованы.
- Бот работает через long polling: нужен постоянно запущенный процесс.
